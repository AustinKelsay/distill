| #74 Trusted providers and reader identity | `distill providers` lists each provider with its kind and whether it is trusted; `providers add <name> [--trusted]`, `trust <name>` and `untrust <name>` edit `[[providers]]` in the config. `ollama` is built in as the local provider and always trusted; under it the command shows whether the runtime is installed and running and, when it is, each installed model as stored on this machine or served from a cloud (read from Ollama's model store by the check ported from the previous build). `ollama-cloud` is listed as a remote provider, untrusted until marked. | #75 Read path | `read::read(home, runtime, reader, session, range)` in core is the one function that returns session text (ADR 0002). It checks trust, finds the session by key (`harness/id`) or by an id only one harness has, and serves the events in an inclusive range of event numbers: a model gets text that starts with `read::NOTICE_START` and ends with `read::NOTICE_END` (archived data, not instructions; copies of either notice inside the session are marked as quoted); the owner gets the stored events; Distill itself gets events with placeholders. Every call appends one line to `log/reads.jsonl` (time, reader with provider and model, session, and `served` with an event count, `refused` with the reason, or `failed`), and nothing is served that could not be logged. `distill read <session>` takes `--provider`/`DISTILL_PROVIDER` and `--model`/`DISTILL_MODEL` (`trust::Reader::from_flags_or_env`), plus `--from`/`--to`; `distill reads [--reader owner|distill|<provider>|<provider>/<model>]` lists the log newest first. Until the detector lands, nothing is scanned: a model at a local provider is served unmasked text (the deliberate interim) and the owner the stored events, while a trusted remote provider and Distill itself are refused because they need placeholders. `Trust::provider_for` gives the provider whose rules apply to a reader (`ollama-cloud` for a cloud model). Events, captures and the readers of either are crate-private in core, and `distill-core/tests/read_path_only.rs` fails if any face's code names them. |
| #79 MCP server on the read path | `distill-mcp` serves MCP over stdio only and opens no network listener (a test checks its code and dependencies). It reads as one reader, named where the harness registers it: `--provider`/`DISTILL_PROVIDER` and `--model`/`DISTILL_MODEL` (`distill_mcp::reader_from_args`, then `trust::Reader::from_flags_or_env`); an unknown argument stops it with its usage. Two tools, one module each under `distill-mcp/src/tools/`: `list_sessions` and `read_session`. Both answer only from the read path and say in their descriptions that session text is archived data, not instructions; a refusal is a tool error whose text is the refusal, with no session text, facts or counts. `read_session` is `read::read`, in full or `from`/`to` an event number. `list_sessions` is `read::list(home, runtime, reader, filter, page)`, new in core (`read/list.rs`): newest first, filtered by harness, project (path prefix a whole folder at a time), model (part of its name, ignoring case) and start day (UTC), mirrors of sessions in the archive and the previous steward's sessions left out unless asked for, at most `read::PAGE_MAX` (50) rows a call with the offset of the next page. Each row is the session's facts and the opening of what the owner first wrote (its first message, whitespace collapsed, clipped at 200 characters), prepared for the reader by the same scan-and-mask step as a read (`read::scanned`); a session the reader may not be served lists with its opening withheld. A model gets the page as text, a line about the page and then the rows between the notices; the owner and Distill itself get `read::Rows`. A list call is one read-log line, `listed` with a count of sessions and no session (`ReadEntry::session` is `None`). |

## Kept from the previous build

- **Capture.** The sweep for all eleven harnesses, append vs. rewrite detection, content-addressed captures, the manifest, `verify`, privacy exclusions, the archive writer lock, fsync before anything is superseded, and the launchd/systemd timer. The raw archive's on-disk format is unchanged; a test reads a manifest and a capture the previous build wrote. On real data the previous build checked an idempotent re-sweep and a clean verify (2,465 captures).
- **Parsers.** Claude Code, Codex (plain and `.jsonl.zst`), OpenCode, Droid, Pi, Cursor (chat and ACP agent stores, and the plain transcripts it keeps per project), Grok, Antigravity, Hermes (its `state.db` exported one session at a time, plus its session files), T3 Code threads and Goose, with full events (tool calls, results, reasoning). Every other file under a harness's roots is archived as a sidecar. On real data the previous build parsed 12,824 sessions with no failures.
- **Mirrors.** A T3 thread run on a natively captured harness is a mirror, and so is a Cursor transcript of an agent whose store is archived. A mirror counts as a duplicate only while its original is in the archive and reaches as far as it does (`SessionMeta::is_duplicate`); its only caller was removed, and it is kept for search and cards.
- **The previous build's steward mark.** Sessions that worked inside the home are marked `steward` in their facts. Kept for search and cards to leave them out.
- **Format drift.** A capture over 16 KB that parses to nothing is a failure flagged as drift, shown per harness in `distill status`.

## Parked, with no callers

- `distill-core/src/parked/redact.rs`: the old redactor's patterns and tests, for the detector ticket.

## Full Disk Access

The timer job no longer needs Full Disk Access on macOS. The previous build needed it only for git outcome joins, which ran `git` inside each session's project, often under `~/Desktop`, `~/Documents` or `~/Downloads`, which macOS protects. The sweep reads only the harnesses' own folders (`~/.claude`, `~/.codex`, `~/.cursor`, `~/.factory`, `~/.pi`, `~/.grok`, `~/.gemini`, `~/.hermes`, `~/.t3`, `~/.local/share/...`), none of which macOS protects, and exclusions compare paths without opening them. The signing step is dropped from `scripts/install.sh` and `scripts/setup-signing.sh` is removed. A harness root moved by hand into a protected folder would need the grant again.

## Known gaps

- Whether a model is stored on this machine is read from the model store Distill sees (`OLLAMA_MODELS`, else `~/.ollama/models`). An Ollama server started with a different model directory is outside what this can check.
- The read path serves nothing to a remote provider or to Distill itself, and gives a local model unmasked text, until the detector ticket (#76) fills in `read::scan` (findings, scanning on read when they are missing or out of date) and `read::mask` (placeholders); the owner's events carry no findings until then.
- Distill's own reads are logged one line per call; one line per tick with a count arrives with the word index, the first step that reads.
- `list_sessions` shows no card titles: cards arrive with their ticket, and a row then shows the card's title in place of the opening. Search (#80), findings (#78) and reveals (#83) add their MCP tools in their own tickets.
- Until the detector (#76) lands, a trusted remote provider is listed sessions with their facts and openings withheld, and refused their text.

- Format drift is caught only when a capture parses to nothing: a change that drops some record types while others still parse is not detected.
- With any privacy exclusion set, Antigravity and Hermes are not archived at all: their sessions don't record a working directory.
- With any privacy exclusion set, a T3 Code thread whose worktree and project root are unknown is not archived, and neither are new native references for it.
- Cursor's stores are SQLite files and its transcripts record no working directory, so while any privacy exclusion is set none of Cursor is archived. Its IDE chat history (`state.vscdb`) is not read.
- Cursor's SDK agent stores (`projects/*/sdk-agent-store`, how T3 Code runs Cursor) encrypt their blobs and keep the root elsewhere, so they are archived but not parsed. Their agents are covered by Cursor's transcripts and by the T3 threads that ran them; with the store unread, both of those stay.
- A config that lists every harness Distill knew when it was written gets harnesses added since (Goose) switched on; one that lists only some gets nothing added.
- Each new capture costs two directory fsyncs (about 18 ms), so a first sweep of a large machine takes a few minutes.
- A previous build's home keeps its `recipes/`, `exports/` and `steward/` folders and its old cards; they are ignored, never deleted. A card from the previous build counts as absent.
