| #75 Read path | `read::read(home, runtime, reader, session, range)` in core is the one function that returns session text (ADR 0002). It checks trust, finds the session by key (`harness/id`) or by an id only one harness has, and serves the events in an inclusive range of event numbers: a model gets text that starts with `read::NOTICE_START` and ends with `read::NOTICE_END` (archived data, not instructions; copies of either notice inside the session are marked as quoted); the owner gets the stored events; Distill itself gets events with placeholders. Every call appends one line to `log/reads.jsonl` (time, reader with provider and model, session, and `served` with an event count, `refused` with the reason, or `failed`), and nothing is served that could not be logged. `distill read <session>` takes `--provider`/`DISTILL_PROVIDER` and `--model`/`DISTILL_MODEL` (`trust::Reader::from_flags_or_env`), plus `--from`/`--to`; `distill reads [--reader owner|distill|<provider>|<provider>/<model>]` lists the log newest first. Until the detector lands, nothing is scanned: a model at a local provider is served unmasked text (the deliberate interim) and the owner the stored events, while a trusted remote provider and Distill itself are refused because they need placeholders. `Trust::provider_for` gives the provider whose rules apply to a reader (`ollama-cloud` for a cloud model). Events, captures and the readers of either are crate-private in core, and `distill-core/tests/read_path_only.rs` fails if any face's code names them. |
| #76 Secret findings and placeholders | The detector (`detect::detect(text)`, `detect::detect_value(json)`) is pure and versioned (`DETECTOR_VERSION` 1): text in, hits out, each a kind and a byte range, none overlapping. It holds the previous build's secret patterns (private keys, Anthropic, OpenAI, GitHub, AWS, Slack, Tinfoil, Google, Stripe, JWT, nostr, bearer tokens), its assignment scanner (`DB_PASSWORD=…`, quoted, YAML blocks, escaped JSON) and its JSON reader (each string decoded; under a credential-named key a string or long number whole, an array per element), and the old suite's secret cases pass as finding cases. `findings::find` places hits in a session's events: an event, a field (its text, or a JSON pointer into a tool call's input, to a value or the key holding it) and a byte range of that decoded string. A finding holds a kind and a fingerprint (HMAC-SHA256 with the key at `keys/fingerprint.key`, made on first use, owner-only), never the value. `findings.json` records the detector version, capture hash, parser version and the key's id; any change makes it out of date. The tick's new `scan` step and `distill scan` scan every session whose findings are missing or out of date, with no limit; `distill status` shows scan progress. The read path scans on read when findings are missing or out of date, refuses the read if that fails, gives the owner the findings with the events, and gives models and Distill itself `[secret: <kind> #<fingerprint>]` in place of each secret, in text and tool-call input. A model at a trusted remote provider is now served. `findings::lookup` finds every fingerprint a short form starts. A leak test runs a planted secret through every command and finds it only in the raw archive and its session's events. The parked redactor is removed; its personal-detail patterns and cases are for #77 (in history at `agent-driven-final`). |

## Kept from the previous build

- **Capture.** The sweep for all eleven harnesses, append vs. rewrite detection, content-addressed captures, the manifest, `verify`, privacy exclusions, the archive writer lock, fsync before anything is superseded, and the launchd/systemd timer. The raw archive's on-disk format is unchanged; a test reads a manifest and a capture the previous build wrote. On real data the previous build checked an idempotent re-sweep and a clean verify (2,465 captures).
- **Parsers.** Claude Code, Codex (plain and `.jsonl.zst`), OpenCode, Droid, Pi, Cursor (chat and ACP agent stores, and the plain transcripts it keeps per project), Grok, Antigravity, Hermes (its `state.db` exported one session at a time, plus its session files), T3 Code threads and Goose, with full events (tool calls, results, reasoning). Every other file under a harness's roots is archived as a sidecar. On real data the previous build parsed 12,824 sessions with no failures.
- **Mirrors.** A T3 thread run on a natively captured harness is a mirror, and so is a Cursor transcript of an agent whose store is archived. A mirror counts as a duplicate only while its original is in the archive and reaches as far as it does (`SessionMeta::is_duplicate`); its only caller was removed, and it is kept for search and cards.
- **The previous build's steward mark.** Sessions that worked inside the home are marked `steward` in their facts. Kept for search and cards to leave them out.
- **Format drift.** A capture over 16 KB that parses to nothing is a failure flagged as drift, shown per harness in `distill status`.

## Full Disk Access

The timer job no longer needs Full Disk Access on macOS. The previous build needed it only for git outcome joins, which ran `git` inside each session's project, often under `~/Desktop`, `~/Documents` or `~/Downloads`, which macOS protects. The sweep reads only the harnesses' own folders (`~/.claude`, `~/.codex`, `~/.cursor`, `~/.factory`, `~/.pi`, `~/.grok`, `~/.gemini`, `~/.hermes`, `~/.t3`, `~/.local/share/...`), none of which macOS protects, and exclusions compare paths without opening them. The signing step is dropped from `scripts/install.sh` and `scripts/setup-signing.sh` is removed. A harness root moved by hand into a protected folder would need the grant again.

## Known gaps

- Whether a model is stored on this machine is read from the model store Distill sees (`OLLAMA_MODELS`, else `~/.ollama/models`). An Ollama server started with a different model directory is outside what this can check.
- The detector finds secrets only. Personal details (email addresses, tailnet names, the owner's username in paths, `personal_terms`) arrive with #77, which adds their kinds and the `personal_terms` hash to what findings are made from.
- Findings go out of date when the fingerprint key changes, so a lost key means every session is scanned again, and its old fingerprints match nothing new.
- Distill's own reads are logged one line per call; one line per tick with a count arrives with the word index, the first step that reads. A call that lists sessions, logged as one line with a count, arrives with search.
- The MCP server has no read tool yet; it will read `DISTILL_PROVIDER` and `DISTILL_MODEL` through `trust::Reader::from_flags_or_env`.

- Format drift is caught only when a capture parses to nothing: a change that drops some record types while others still parse is not detected.
- With any privacy exclusion set, Antigravity and Hermes are not archived at all: their sessions don't record a working directory.
- With any privacy exclusion set, a T3 Code thread whose worktree and project root are unknown is not archived, and neither are new native references for it.
- Cursor's stores are SQLite files and its transcripts record no working directory, so while any privacy exclusion is set none of Cursor is archived. Its IDE chat history (`state.vscdb`) is not read.
- Cursor's SDK agent stores (`projects/*/sdk-agent-store`, how T3 Code runs Cursor) encrypt their blobs and keep the root elsewhere, so they are archived but not parsed. Their agents are covered by Cursor's transcripts and by the T3 threads that ran them; with the store unread, both of those stay.
- A config that lists every harness Distill knew when it was written gets harnesses added since (Goose) switched on; one that lists only some gets nothing added.
- Each new capture costs two directory fsyncs (about 18 ms), so a first sweep of a large machine takes a few minutes.
- A previous build's home keeps its `recipes/`, `exports/` and `steward/` folders and its old cards; they are ignored, never deleted. A card from the previous build counts as absent.
