## Known gaps

- Format drift is caught only when a capture parses to nothing: a change that drops some record types while others still parse is not detected.
- A slugged address at a non-provider domain (`jdoe-example-org`) is redacted only when the address itself follows it (a contact list); alone it is kept, because a rule broad enough to catch it also rewrites ordinary names like `my-github-org`.
- Recipe proposals can use only the filter fields recipes have (sources, card quality, outcomes and tags, date, tool calls).
- Commits are attributed only when the session recorded its branch and that branch still exists (on this machine, 276 of 1,863 sessions in a git repo); other work on the same branch in the window is counted too.
- First normalize runs git once or twice per session (about 75 s for 2,000 sessions); later runs skip unchanged captures.
- No t3code join: its database was locked when checked and its contents are unverified.
- T3 thread titles aren't in the archive (they change while a thread lives); titles fall back to the first user message.
- With any privacy exclusion set, Antigravity and Hermes are not archived at all: their sessions don't record a working directory.
- With any privacy exclusion set, a T3 Code thread whose worktree and project root are unknown is not archived, and neither are new native references for it.
- Cursor's stores are SQLite files and its transcripts record no working directory, so while any privacy exclusion is set none of Cursor is archived. Its IDE chat history (`state.vscdb`) is not read.
- Cursor's SDK agent stores (`projects/*/sdk-agent-store`, how T3 Code runs Cursor) encrypt their blobs (the key is in the store's `meta`) and keep the root elsewhere, so they are archived but not parsed. Their agents are covered by Cursor's transcripts and by the T3 threads that ran them; with the store unread, both of those stay.
- A config that lists every source Distill knew when it was written gets sources added since (Goose) switched on; one that lists only some sources gets nothing added.
- Each new capture costs two directory fsyncs (about 18 ms), so a first sweep of a large machine takes a few minutes.
