| #74 Trusted providers and reader identity | `distill providers` lists each provider with its kind and whether it is trusted; `providers add <name> [--trusted]`, `trust <name>` and `untrust <name>` edit `[[providers]]` in the config. `ollama` is built in as the local provider and always trusted; under it the command shows whether the runtime is installed and running and, when it is, each installed model as stored on this machine or served from a cloud (read from Ollama's model store by the check ported from the previous build). `ollama-cloud` is listed as a remote provider, untrusted until marked. | #75 Read path | `read::read(home, runtime, reader, session, range)` in core is the one function that returns session text (ADR 0002). It checks trust, finds the session by key (`harness/id`) or by an id only one harness has, and serves the events in an inclusive range of event numbers: a model gets text that starts with `read::NOTICE_START` and ends with `read::NOTICE_END` (archived data, not instructions; copies of either notice inside the session are marked as quoted); the owner gets the stored events; Distill itself gets events with placeholders. Every call appends one line to `log/reads.jsonl` (time, reader with provider and model, session, and `served` with an event count, `refused` with the reason, or `failed`), and nothing is served that could not be logged. `distill read <session>` takes `--provider`/`DISTILL_PROVIDER` and `--model`/`DISTILL_MODEL` (`trust::Reader::from_flags_or_env`), plus `--from`/`--to`; `distill reads [--reader owner|distill|<provider>|<provider>/<model>]` lists the log newest first. Until the detector lands, nothing is scanned: a model at a local provider is served unmasked text (the deliberate interim) and the owner the stored events, while a trusted remote provider and Distill itself are refused because they need placeholders (#76 replaced this interim). `Trust::provider_for` gives the provider whose rules apply to a reader (`ollama-cloud` for a cloud model). Events, captures and the readers of either are crate-private in core, and `distill-core/tests/read_path_only.rs` fails if any face's code names them. |
| #76 Secret findings and placeholders | The detector (`detect::detect(text)`, `detect::detect_value(json)`) is pure and versioned (`DETECTOR_VERSION` 1): text in, hits out, each a kind and a byte range, none overlapping. It holds the previous build's secret patterns (private keys, Anthropic, OpenAI, GitHub, AWS, Slack, Tinfoil, Google, Stripe, JWT, nostr, bearer tokens), its assignment scanner (`DB_PASSWORD=…`, quoted, YAML blocks, escaped JSON) and its JSON reader (each string decoded; under a credential-named key a string or any number whole, an array per element), and the old suite's secret cases pass as finding cases. `findings::find` places hits in a session's events: an event, a field (its text, or a path of positions into a tool call's input, to a value or the key holding it; never key text, since a key can be a secret) and a byte range of that decoded string. A finding holds a kind and a fingerprint (HMAC-SHA256 with the key at `keys/fingerprint.key`, made on first use, owner-only), never the value. `findings.json` records the detector version, capture hash, parser version and the key's id; any change makes it out of date. The tick's new `scan` step and `distill scan` scan every session whose findings are missing or out of date, with no limit; `distill status` shows scan progress. The read path scans on read when findings are missing or out of date, refuses the read if that fails, gives the owner the findings with the events, and gives models and Distill itself `[secret: <kind> #<fingerprint>]` in place of each secret, in text and tool-call input. A model at a trusted remote provider is now served. `findings::lookup` finds every fingerprint a short form starts. A leak test runs a planted secret through every command and finds it only in the raw archive and its session's events. The parked redactor is removed; its personal-detail patterns and cases are for #77 (in history at `agent-driven-final`). |
| #77 Personal-detail findings | The detector is now a `detect::Detector`, made from a `detect::Owner` (the owner's username, taken from the home folder's name, and the config's `personal_terms`; `findings::owner(config)`), and is at `DETECTOR_VERSION` 2. After the secret rules it finds email addresses (not `git@`, `noreply@`, `no-reply@`), addresses written as slugs (at a mail provider's domain, or at any domain when a person's address follows on the line), tailnet hosts, tailnet names (cut short or slugged) and addresses in `100.64.0.0/10` and `fd7a:115c:a1e0::/48`, the username as a folder after `/Users/` or `/home/`, and each of `personal_terms` as a whole word or phrase, ignoring case. The old suite's personal-detail cases pass as finding cases, the slug-before-an-address rule restated to read the original text. |

| #80 Word search | The word index (`distill_core::index`) is the tick's new `index` step, after `scan`. It reads every session whose entry is missing or out of date through the read path as Distill itself (`read::for_index`), so each secret is already a placeholder, and the whole step is one read-log line, `indexed` with counts of sessions and events. It lives in `index/words/`: a manifest with one entry per session recording what it was built from (capture hash and parser version, which name its events, and a digest of its secret findings), and immutable segment files of words and their postings; a changed session is written to a new segment and old copies are dropped as segments merge (at most 8). Ranking is BM25 over the current copies only, so deleting the index and running the tick gives the same results. Words are runs of letters, digits and `_`, ignoring case; a part of a snake_case word finds it, and a placeholder's kind and fingerprint are words. A query is answered from the index; only the page's sessions are read. `read::search(home, runtime, reader, query, filter, page)` takes `read::Filter` (harness, project, model, dates, mirrors and the previous steward's sessions left out unless asked for) and returns, best first, each session's facts, the opening of what the owner first wrote and the matching passage, prepared for that reader by the read path (the owner gets the stored passage with its findings); a call is one `listed` read-log line with a count and never the query. `distill search <words> --provider … [--harness --project --used-model --since --until --mirrors --steward --offset --limit]` and the MCP tool `search_sessions` are its faces. `distill status` shows index progress. The leak test runs the index and searches, checks every file under the home, and the MCP half calls every tool the server lists. No new crate. |
| #81 Cards from a local model | The tick's new `cards` step, after `index` (`tick::STEPS`; `tick::tick_with` takes the local runtime, `tick::tick` uses Ollama on this machine), runs `cards::write`: for every session but mirrors of sessions in the archive and the previous steward's sessions (`cards::wanted`), newest first and up to `sessions_per_run`, it reads the session through the read path as `ollama/<card_model>` (one `served` read-log line each; the model sees placeholders), cuts it to `cards::SESSION_BUDGET` bytes keeping its start and its closing notice, and asks `card_model` through the local client with `cards::PROMPT` (`PROMPT_VERSION` 1). The answer must be one JSON object of `title`, `summary`, `tags` and `outcome` (`done`, `partly_done`, `failed`, `unknown`), alone or in one code fence, within limits (`cards::parse_reply`); anything else is a failure for that session, recorded in `state/cards.json` (`Home::card_failures_path`) and retried after the sessions never tried. A card (`card.json`, `CARD_FORMAT` 1) records its model, prompt version, when it was written and what it was built from (`findings::BuiltFrom`: capture hash, parser version and a digest of the secret findings); when either changes it is out of date, is shown to no one, and is written again. A card of another shape (the previous build's) counts as absent. Card text is scanned like session text: its findings go in `findings.json` under `card`, with the card's field names (`title`, `summary`, `tags/<n>`) as their place and the card's hash; a card that holds a secret is not written (counted `discarded`), and a stored card a later scan finds a secret in is deleted, so both are written again. With `card_model` not set, no runtime, the runtime stopped or the model not stored here, the step is skipped and says why. The run log gets the step's counts (sessions, current, pending, written, failed, discarded), failures and skip. `distill status` shows card progress (`Status::cards`: current, pending, failing, and why the step is skipped). The word index holds each current card's title, summary and tags (`index::MadeFrom` records the card's hash; `INDEX_VERSION` 2), so a card's words find its session, and a card written after the index step joins the index at the next tick. `read::list` and `read::search` rows carry `card` (`cards::Shown`: the card, with its findings for the owner); a model reads the card's title, outcome, tags and summary in place of the opening. `read::Filter` gains `tag` and `outcome`, matched against current cards only; faces: `distill search --tag --outcome`, and `tag`/`outcome` on the MCP tools `list_sessions` and `search_sessions`. The leak tests run a model whose reply echoes a planted secret: its card is discarded, the next card holds only the placeholder, and no file under the home but the raw archive and the session's events holds a value. |
| #82 Search by meaning | The tick's new `vectors` step, after `cards` (`tick::STEPS`), runs `index::vectors::build`: for every session that gets a card (`cards::wanted`), newest first and up to `sessions_per_run`, it reads the session through the read path for `ollama/<embedding_model>` (`read::for_embedding`, the same placeholders as the word index; one `indexed` read-log line under the model's name) and embeds, through the local client, what the owner wrote (user messages with placeholders, in pieces of at most `vectors::CHUNK` bytes, at most `MAX_CHUNKS` spread over the session) and the current card's summary, in one call per session. The vectors are one flat file, `index/vectors.bin` (`Home::vectors_path`; `VECTORS_VERSION` 1): a JSON header naming the model and, per session, what it was built from (`index::MadeFrom`: capture hash, parser version, secret-findings digest and card hash) and each vector's event, then the vectors as unit-length `f32`s. A session's vectors are rebuilt when its events, secret findings or card change; a file of another model or version is rebuilt whole; deleting it and running the tick gives the same file. Search embeds the query with the same model and scores each session by its closest vector (cosine above 0, at most `vectors::MEANING_TOP` sessions); `read::search` merges that list (`Source::Meaning`) with the word list by reciprocal rank, so `distill search` and `search_sessions` return one ranked list, and a meaning-only hit's passage is the owner's message its vector starts at. A query the detector finds a secret in, or with a word whose fingerprint is a secret's in the index, is never embedded. With `embedding_model` not set, no runtime, the runtime stopped, the model not stored here, or no vectors yet, the step is skipped and says why, and search finds by words alone: `Hits::meaning` is `Meaning::Skipped(why)` and a model reads "Search by meaning is off (why), so these are word matches only." `distill status` shows vector progress (`Status::vectors`: current, pending, vectors, bytes, and why the step is skipped). The leak tests embed a session with planted secrets and search by meaning: no text sent to the embedder holds a value, and no file under the home but the raw archive and the session's events does. Since the cutover (#91) it runs against a real local embedding model; the top-five check of loose descriptions waits for the backfill (below). |
| #83 Reveal requests | `reveal::request(home, runtime, reader, session, fingerprints, reason)` in core files a request for specific secrets in one session, named by the fingerprints their placeholders show (`a1b2c3d4`, `#a1b2c3d4` or the whole placeholder; each matches the session's secrets it starts), and returns a request with a 16-hex-character ID and no value. Only a model at a trusted provider may file one; the owner, Distill itself and an untrusted or unnamed reader are refused, and so are a request with no reason, a reason the detector finds a secret in, or a fingerprint the session holds no secret for. ## Known gaps

- The exposure check sees listeners only through `lsof`, and only Distill's own processes running when it runs. Without `lsof` (some Linux installs) that rule is unchecked. On Linux the disk counts as encrypted only on a dm-crypt device; fscrypt or an encrypted home folder shows as unknown. Files made before #90 keep their modes until `distill exposure --fix`. The timer's own unit files (`~/Library/LaunchAgents`, `~/.config/systemd/user`) are outside the home and keep the usual modes; they hold paths, not session data.
- The pruning check reads the owner's own harness settings and Claude Code's managed settings files, not project-level settings (a project's `.claude/settings.json` can shorten `cleanupPeriodDays`), MDM profiles or server-managed settings. Antigravity's trimming by size and every in-place rewrite have no setting to read (see `docs/harness-pruning.md`).
- OpenCode's spilled tool outputs are looked for only in `tool-output/` beside the database Distill reads: with `OPENCODE_DB` set to a database elsewhere they stay in OpenCode's data folder and are not captured. Spills OpenCode deleted before the first sweep with #107 are gone, so their tool results keep the preview.
- Whether a model is stored on this machine is read from the model store Distill sees (`OLLAMA_MODELS`, else `~/.ollama/models`). An Ollama server started with a different model directory is outside what this can check.
- Names of people, postal addresses, phone numbers and client names are found only by the local model's pass (#88), only in what the owner and the agent wrote, and only once it has run: until then, or with no model set, a session has none. A detail cut across two parts of a long session can be missed, and a long session costs one model call per part. Ollama is asked for JSON mode, so the reply is one JSON object; a reply that is still not the expected list fails under the strict parse, as for cards. The pass's findings are not rewritten when `PROMPT` changes unless `MODEL_DETECTOR_VERSION` is bumped.
- Findings go out of date when the fingerprint key changes, so a lost key means every session is scanned again, and its old fingerprints match nothing new.
- Words longer than 64 characters are not indexed, and there is no phrase or prefix search.
- Search by meaning runs against the real local embedding model since the cutover (#91), but the ticket's check of loose descriptions finding their sessions in the top five (recorded on #82) waits for the vectors' backfill. Tests use the fake runtime's fixed vectors. No prefix such as `search_query:` is added for models that expect one.
- Mirrors and the previous steward's sessions get no vectors, so with `--mirrors` or `--steward` only words find them. A card written by a tick is embedded in the same tick, since the vectors step runs after the card step. A query is embedded once per search, so search by meaning waits on the local runtime; the whole vectors file is read for each search.
- A card written by a tick joins the word index at the next tick, because the index step runs before the card step.
- The GUI covers findings with a chip rather than blurring them (#84's outcome); ADR 0007 and spec story 52 say "blurred". The list's chips are not clickable: a finding is shown only in an open session. A covered secret in the session view still copies as its chip, and a shown one copies as its value. The session view has no search inside a session and no jump to the passage a search matched; it reads the whole session at once.
- Ollama is asked for JSON mode (`"format": "json"`), so a model that would think aloud or wrap its card in prose still answers with one JSON object. A reply that is not the expected card fails under the strict parse; such a session stays failing and is retried after the rest.

- A session opened from Findings or Approvals is headed by its key, not its card: core's card for it comes only with a list or search. Approvals shows only pending requests; answered, collected and expired ones are in the read log. The read log screen reads the whole log file for each page.
- Setup cannot move the home: it shows the folder `DISTILL_HOME` (or `~/distill`) names, because the next launch and the timer resolve it the same way. Setup does not set `sessions_per_run`.
- A reveal request's expiry is recorded when the next call touches requests (listing, answering or collecting), not at the moment it passes; status counts only requests that have not passed it.

- Format drift inside a record type a parser knows (a renamed field, a `user` record with no message) is not counted, and neither are records with no type name; only a capture that then parses to nothing shows it. The parsers' `IGNORED` lists hold what their code and tests skip on purpose plus types known to be bookkeeping; the first parse after #104 may name more, each to be added to its list or parsed.
- With any privacy exclusion set, Antigravity and Hermes are not archived at all: their sessions don't record a working directory.
- With any privacy exclusion set, a T3 Code thread whose worktree and project root are unknown is not archived, and neither are new native references for it.
- Cursor's stores are SQLite files and its transcripts record no working directory, so while any privacy exclusion is set none of Cursor is archived. Its IDE chat history (`state.vscdb`) is not read.
- Cursor's SDK agent stores (`projects/*/sdk-agent-store`, how T3 Code runs Cursor) encrypt their blobs and keep the root elsewhere, so they are archived but not parsed. Their agents are covered by Cursor's transcripts and by the T3 threads that ran them; with the store unread, both of those stay.
- A config that lists every harness Distill knew when it was written gets harnesses added since (Goose) switched on; one that lists only some gets nothing added.
- Each new capture costs two directory fsyncs (about 18 ms), so a first sweep of a large machine takes a few minutes.
- A previous build's home keeps its `recipes/`, `exports/` and `steward/` folders and its old cards; they are ignored, never deleted. A card from the previous build counts as absent.
