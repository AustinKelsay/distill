# DISTILL agent guide

- DISTILL is a private, searchable archive of the owner's agent sessions. Terms are in `GLOSSARY.md`, decisions in `docs/adr/`, and known limits in `docs/known-gaps.md`; read them before changing behavior, and update `docs/known-gaps.md` when a change adds or removes a limit. The original spec is issue #72.
- Workspace: `crates/distill-core` (all behavior), `distill-cli` (`distill` binary), `distill-mcp` (stdio MCP server), `distill-gui` (Rune window; the only crate that depends on Rune), `distill-eval` (judges the model steps with a trusted provider's real models against a copy of a home; not installed, not a default member, and the only crate that turns on `distill-core`'s `eval` feature). The faces hold no logic. The CLI has one module per command (`distill-cli/src/commands/`) and the MCP server one per tool (`distill-mcp/src/tools/`). The GUI has one module per screen (`distill-gui/src/screens/`, listed in `nav::SCREENS`); its calls into core run as jobs off the frame loop (`jobs.rs`), and every scene in `fixture::SCENES` is checked against `crates/distill-gui/snapshots/`.
- Capture is `sweep.rs`, `archive.rs`, `harness.rs` and `schedule.rs`, and on a hub the pull from its spokes, `machines.rs` (ADR 0010); the parsers are `normalize/` (ADR 0001). The tick runs the steps declared in `tick::STEPS`; the model steps share one time budget per tick (`tick::model_budget`) and stop taking sessions at their `tick::Deadline`. Status is one report in `status.rs`. `Home` has a path helper for every entry of the home's layout; use it rather than joining paths. A new kind of file in the home also gets a `Home::keep` entry saying whether a backup holds it (ADR 0009); `tests/owner_only_after_every_step.rs` fails otherwise.
- The raw archive (`raw/`, and on a hub each spoke's `machines/<machine>/raw/`, ADR 0010) is append-only (a blob that a longer append of the same file supersedes is dropped) and its on-disk format never changes. Only `archive.rs` writes it. Everything under `sessions/`, `index/` and `state/` must stay rebuildable from the raw archives. A spoke's sessions carry their machine and are keyed `<machine>:<harness>/<id>`; the home's own keep `<harness>/<id>`.
- Session text leaves DISTILL readable only through the read path (the `read` module, `read.rs` and `read/`; ADR 0002), which checks trust and writes the read log. Two other ways out exist, and neither is a read. A backup carries the backup set encrypted on this machine, under keyed object names, to an adapter that never sees a key, and writes the backup log (ADR 0009). A spoke's export (`machines::export`, through `archive::export`) carries its raw captures over SSH to the owner's own hub, and writes the export log (ADR 0010). No face reads events or captures directly; `crates/distill-core/tests/read_path_only.rs` fails if one does. Reveal approval and denial exist only in the GUI (ADR 0004); `crates/distill-core/tests/approval_in_gui_only.rs` fails otherwise. The owner's tag edits (`tags::tag_session`) come only from the GUI and the CLI, never MCP; `crates/distill-core/tests/owner_tags_not_from_mcp.rs` fails otherwise. No crate opens a network listener. Every file and folder DISTILL creates in the home is owner-only; new code uses `util::create_dir_private` and `util::private_file`, and `distill exposure --fix` repairs older modes.
- Parsers live in `normalize/<harness>.rs`. When a parser's output changes, bump its `parser_version` in `normalize/mod.rs` and add a test with a small synthetic sample. A record type a parser skips on purpose goes in its `IGNORED` list. When what the parse step derives beyond the parsers changes, bump `META_VERSION`. Never commit real session text, paths, or secrets as fixtures.
- The detector (`detect/`) is pure (text in, hits out); bump `DETECTOR_VERSION` whenever what it finds changes, and add a finding case to `detect/tests.rs`. `findings.rs` places hits in a session's events, owns the fingerprint key, and keeps `findings.json` current. Test secrets are fake and built from pieces at run time.
- The word index (`index/`) reads sessions only through `read::for_index`, so it never holds a secret's value; bump `INDEX_VERSION` whenever what it indexes or its file format changes. The vectors (`index/vectors.rs`) read only through `read::for_embedding` and embed only what the owner wrote and the card summary; a query is not embedded when the detector finds a secret in it, or when a piece of it (split at spaces, `=`, `:`, `,`, `;`, quotes and round brackets) 8 or more bytes long has a short fingerprint already in the word index (`vectors::holds_secret`); any other query, personal details included, is embedded as written. Bump `VECTORS_VERSION` whenever what is embedded or the file format changes.
- The model steps (cards, `cards.rs`; personal details, `details.rs`) read through the read path as `<runtime.provider()>/<model>`: Ollama on this machine, or the trusted provider in `[steward.generation]` (ADR 0008). Embeddings always run in Ollama. Replies are parsed strictly (`cards::parse_reply`, `details::parse_reply`). Bump `cards::PROMPT_VERSION` when `cards::PROMPT` changes, `CARD_FORMAT` when a card's shape changes, and `details::MODEL_DETECTOR_VERSION` when `details::PROMPT` changes. Tests use `FakeRuntime` only.
- The owner's live archive is `~/distill`, and an hourly timer runs the installed binary against it. Run every build, test and GUI session against a temporary home. Installing (`scripts/install.sh`, `cargo install`) replaces the binaries the timer runs (and, on macOS, `~/Applications/DISTILL.app`, built by `scripts/mac-app.sh`, whose window finds the `distill` command through `DISTILL_CLI`), and `schedule install` or the GUI's Finish replaces the live `dev.distill.tick` job whatever `HOME` is; only the owner installs. A test that reaches the timer installer stubs `launchctl` (and `systemctl` on Linux).
- Commands: `cargo test` (default members: no GUI, no eval), `cargo test -p distill-gui`, `cargo test -p distill-eval`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check`. After an intended GUI change, `DISTILL_UPDATE_SNAPSHOTS=1 cargo test -p distill-gui` (see `crates/distill-gui/snapshots/README.md`).
- Rune is pinned to one `dev` rev: the dependency in `crates/distill-gui/Cargo.toml` and the `[patch.crates-io]` entries in the root `Cargo.toml`; bump them together.

## Agent skills

### Issue tracker

Issues and specs live in this repo's GitHub Issues (`gh` CLI). See `docs/agents/issue-tracker.md`.

### Triage labels

The five default labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Domain docs

Single context: `GLOSSARY.md` at the root, decisions in `docs/adr/`. See `docs/agents/domain.md`.
